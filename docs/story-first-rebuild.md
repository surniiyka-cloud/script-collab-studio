# Story Studio — перезапуск интерфейса / пять этапов

**Ветка:** `chatgpt/rebuild-story-workflow` (на базе экспериментальной `chatgpt/feature-script-to-film-pipeline`). **Черновик, не слито в main.** Прежние проекты, аккаунты, бинарные файлы, сценарии и Yjs-документы сохраняются. Старый экран студии не показывается на маршруте проекта; он оставлен в истории для безопасного отката.

## Новая продуктовая модель

Один последовательный рабочий маршрут вместо трёх запутанных вкладок.

1. **Готовый сценарий.** Импорт TXT/Fountain/MD/DOCX/PDF, обзор автоматически выделенных сцен, имён говорящих, авторских действий, диалогов и заголовков локаций. Пользователь видит результат *до* записи и подтверждает импорт. Текст не переписывается. Для уже импортированного сценария можно просто продолжить к шагу 2.
2. **Персонажи.** После разбора имена появляются в списке. Можно добавить вручную; **выбрать много фотографий за один раз**, назначить каждой фотографию имя через выпадающий список и сохранить в S3. У одного героя несколько референсов. Пользователь управляет соответствием фотографии персонажу, распознавание лиц не используется.
3. **Локации.** Автоматически создаются из новых названий сцен; прежние сценарии предлагают найденные названия к созданию. Можно добавлять другие локации. Многофайловая загрузка локаций с назначением фото конкретному месту. Для каждой сцены указана привязанная локация, можно изменить вручную. Описание локации выводится из авторских действий, не придумывается.
4. **Кадры сцены.** Непосредственно внутри конкретной сцены — контекст (место, говорящие, действия, реплики), фото-кадры и упорядоченный список. Кадры можно вручную добавлять, редактировать, сохранять и менять местами стрелками, порядок хранится в metadata. Кнопка «Предложить планы по тексту» строит *текстовые* предложения на основе оригинальных строк, фотографии надо загрузить отдельно. При переходе по сценам контекст меняется.
5. **Карта истории.** Единую последовательность сцен показываем структурными блоками, каждый содержит фото локации, референсы говорящих персонажей, авторские действия и реплики, картинки раскадровки в порядке кадров и ссылку на редактирование сцены.

**Что не обещаем:** этот мастер пока не придумывает неизвестные факты, не создаёт изображения без модели, не генерирует видео или музыку. Извлекает известное из сценария, а не автоматически дописывает авторский материал. Ветка Stage 5 ранее содержала экспериментальные адаптеры Ollama/ComfyUI, но они не являются обязательным или центральным элементом новой последовательности; они могут быть включены позднее как отдельные функции.

## Основные изменения в коде

- New project route: `apps/web/src/screens/StoryWizardScreen.tsx` and `story-wizard.css`.
- Story query: `GET /api/v1/projects/:projectId/workflow/story?scriptId=…` — returns original per-scene Yjs blocks, dialogue with speaker, action descriptions, recognised characters, scene location and ordered SHOT nodes with private media metadata.
- `POST /api/v1/projects/:projectId/workflow/locations` — add/reuse location in project.
- `PUT /api/v1/scenes/:sceneId/workflow/location` — validate project ownership and set locationId for scene's SCENE node.
- Import creates LOCATION nodes based on heading place name and links them via SCENE node's metadata (no database migration required).
- Existing role-based authorization, API and private media endpoint reused. LOCATION nodes now allow photo uploads.
- The project index remains for selecting and creating projects.

## Чего ждём от первой проверки

В Codespaces:
```bash
git fetch origin
git switch --track origin/chatgpt/rebuild-story-workflow
pnpm install --no-frozen-lockfile
pnpm build
pnpm test:logic
bash scripts/verify-production.sh
```
Если ветка создана локально ранее, используйте `git switch chatgpt/rebuild-story-workflow` и `git pull --ff-only` вместо `--track`. Перед переключением `git status --short` и сохранение своих изменений. `main` не меняем.

После сборки:
```bash
docker compose up -d postgres objectstore
pnpm dev
```
Открыть порт 5173 в Codespaces и существующий или тестовый проект. Проверить 5 шагов по порядку. В частности: два героя с репликами, две локации, пачка из 4–6 фотографий с распределением имён/мест, ручное добавление кадра для каждой сцены и итоговую схему. Обновить страницу: фото, локации и сцены должны остаться на месте.

Проверить безопасность: Viewer не может сохранять или загружать файлы (серверная проверка); фотографии нельзя читать без Bearer JWT / membership; нельзя присвоить сцене локацию другого проекта.

**Не выполнено в этой сессии:** сборка TypeScript, работа в реальном браузере, bulk upload и end-to-end проверка всех пяти шагов. До тестирования это draft, не production release.

## Regression: реальный формат «Миссия 52», версия 3.0

Пользователь проверил импорт DOCX с обычными титульными строками, заголовками `ПРОЛОГ. РЫБАЛКА`, `01. НАЗАД В БУДУЩЕЕ` … `12. ОСОБЕННОСТИ НАЦИОНАЛЬНОЙ РЫБАЛКИ`, `ЭПИЛОГ. БАЙКАЛ`, временем `00:00–00:50 · Тихий берег. Раннее утро` и репликами `СА: …` / `СА (улыбается): …`. Прежний парсер ошибочно показывал одну сцену и ноль персонажей.

Исправлено в этой ветке:
- [x] Заголовки пролога, эпилога, нумерованные `01.`–`12.` даже с другим стилем DOCX, плюс старые `ИНТ.`/`НАТ.`.
- [x] Разделение таймкода, локации и времени суток из строки `00:00–00:50 · …`.
- [x] Распознавание реплики `ГОВОРЯЩИЙ: текст` и `ГОВОРЯЩИЙ (ремарка): текст` без изменения оригинальных строк. Режиссёрская ремарка сохраняется отдельно от произнесённой реплики. Закадровый голос остаётся речевой дорожкой, не автоматически фото-персонажем.
- [x] Прозаические двоеточия (`Он раскрывает ладони: …`, `На экране: …`), а также `ПЕРЕХОД: …` не создают ложных персонажей.
- [x] Титульные строки перед первой главой больше не становятся фиктивной сценой; полный оригинальный исходник хранится отдельно в `YDocState('script:<id>:source')`.
- [x] Обогащён предварительный просмотр — по сценам время, место, список говорящих и возможность раскрыть **все действия и диалоги**, прежде чем сохранить сценарий.
- [x] В итоговой карте истории отображается таймкод, авторские действия и диалоги каждой сцены.

**Проверка на самом прикреплённом DOCX:** по параграфам файла и тем же регулярным выражениям локальная инспекция распознала 14 глав, 14 временных диапазонов и 26 различных меток говорящих (включая «ГОЛОС ЗА КАДРОМ», который не является обычным фотоперсонажем). Это диагностическая проверка на исходном файле, **не доказательство**, что вся сборка сайта уже прошла TypeScript и интеграцию. Для этого добавлены новые unit/HTTP проверки; пользователь запускает Codespaces.

До подтверждения правильного предпросмотра **не нажимать** кнопку сохранения. Если пользователь уже подтвердил неверный импорт ранее, загрузить DOCX заново после обновления и выбрать новый сценарий; существующий ошибочный экземпляр останется в проекте, ничего не удаляется автоматически.
